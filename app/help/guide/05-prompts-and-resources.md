# Prompts and resources: the skills

A **skill** is an instruction several consumers must apply the same way, owned in the console. Your app receives the
skills offered to it in two forms:

- **a prompt** — `prompts/list` names them with their arguments; `prompts/get` returns the instruction with the
  arguments filled in (`{{kb_tool}}` becomes what you pass; a required argument must be given).
- **a resource** — `resources/list` names them as `skill://{name}` (`text/markdown`); `resources/read` returns the
  text as written, placeholders unresolved. This is the form a client that loads skills as files uses.

Over REST, `POST /skills/{name}/render` with `{"arguments": {...}}` returns what `prompts/get` would.

## How to use one

Put the rendered text in the system prompt, or in a user turn before the task, as your orchestration prefers. A skill
may name the **tools** it expects (`search_knowledge_base`): offer those tools to the model with it.

## The starters

| Skill | Apps | What it says |
|---|---|---|
| `cite_with_tag` | tutor, slides | cite a knowledge-base passage with its tag exactly as returned |
| `pt_pt_style` | tutor, slides, agent_runtime | write European Portuguese |
| `ai_generated_disclosure` | job2cool, agent_runtime | say once that the answer was generated by a model |
